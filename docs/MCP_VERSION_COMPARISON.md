# MCP 版本对比 - 如何选择适合你的 MCP 服务

> 📊 详细对比简化版和企业版 MCP 服务的差异和选择建议

## 🎯 快速决策

### 我应该选哪个版本？

**回答以下问题**:

1. **你是个人开发者吗？** → 🟢 选择**简化版**
2. **你需要快速测试功能吗？** → 🟢 选择**简化版**
3. **你是第一次使用 MCP 吗？** → 🟢 选择**简化版**
4. **你需要部署到生产环境吗？** → 🟡 选择**企业版**
5. **你需要处理高并发请求吗？** → 🟡 选择**企业版**
6. **你需要监控和日志分析吗？** → 🟡 选择**企业版**

**简单规则**:
- ✅ **80% 的用户** → 简化版就够用了
- ✅ **学习和开发** → 从简化版开始
- ✅ **企业生产环境** → 使用企业版

## 🔄 升级路径

### 从简化版升级到企业版

**何时需要升级？**
- ✅ 用户数超过 5 人
- ✅ 需要性能监控
- ✅ 响应时间要求 < 100ms
- ✅ 需要高可用性保障

**升级步骤**:

```bash
# 1. 停止简化版（按 Ctrl+C）

# 2. 进入企业版目录
cd /home/CapCutAPI-1.1.0/mcp_bridge

# 3. 安装依赖
pip install -r requirements.txt

# 4. 配置 Redis
# 编辑 config/unified_config.yaml

# 5. 启动企业版
./manage.sh start

# 6. 验证服务
curl http://localhost:8082/health
```

**迁移成本**:
- 配置迁移: < 1 小时
- 客户端配置: 只需修改连接地址
- 数据迁移: 无需迁移（都调用同一个 CapCut API）

## ❓ 常见问题

### Q: 简化版的性能真的够用吗？
**A**: 对于个人使用和小规模自动化，简化版完全够用。测试显示，单用户场景下，简化版和企业版的响应速度差异小于 100ms，用户几乎感觉不到差别。

### Q: 可以同时运行两个版本吗？
**A**: 可以！它们使用不同的端口和配置，完全独立。你可以用简化版做开发测试，企业版做生产服务。

### Q: 从简化版升级到企业版，数据会丢失吗？
**A**: 不会。两个版本都调用同一个 CapCut API，草稿数据存储在 CapCut API 层面，切换版本不影响数据。

### Q: 企业版一定需要 Redis 吗？
**A**: 理论上可以禁用 Redis，但会失去缓存优化，性能大幅下降。如果不需要 Redis，建议直接使用简化版。

### Q: 简化版有什么限制吗？
**A**: 主要限制是并发性能。如果你的场景只有 1-5 个并发请求，简化版完全够用。超过 10 个并发，建议使用企业版。
